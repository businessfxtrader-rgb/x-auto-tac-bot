# x-auto-tac-bot

TAC_FXtrade(YouTube「TACテクニカル分析講座」の公式X)の自動投稿ボット。
GitHub Actions + cron-job.org(外部トリガー、15分おき)で、2種類の投稿を自動化している。

| 投稿 | 時刻(JST) | スクリプト | 内容 |
|---|---|---|---|
| AI生成投稿 | 平日13:00(1回)/ 土日7:30・19:00(2回) | `tac-post.js` | Claude Codeが話題・切り口を変えて文章を生成し投稿 |
| ドル円レート発表 | 平日8:00以降(1回、土日はスキップ) | `rate-post.js` | Yahoo Financeの現在レートを固定フォーマット+画像で投稿(AI不使用) |

各スクリプトは「時刻が来ていて本日未投稿か」だけを判定するため、起動が遅延しても自動でキャッチアップする。
状態は `state.json`(AI投稿)・`rate-state.json`(レート投稿)に保存される。

## ドル円レート投稿の仕様

```
サトシ「ピカチュウ！かわせ！」

ピカチュウ「米ドル/円　157.78」   ← 小数点2桁、全角スペース区切り
[画像: rate-announce.jpg]
```

- レート取得: Yahoo Finance(`USDJPY=X`)。取得失敗・異常値・4日以上古い値は投稿せず、次回の起動で再試行
- 画像: `rate-announce.jpg` を差し替えれば画像を変更できる(5MB以下のJPEG)
- 動作確認: `node rate-post.js --dry-run`(投稿せず、レート取得と文面のみ確認)。
  GitHub上で試す場合は Actions → TAC Auto Post → Run workflow で `rate_dry_run` にチェック

## 管理シート(Googleスプレッドシート)への記録

Botの動きを、非公開の管理シートに記録する。書き込みはサービスアカウント(`sheet.js`、依存ライブラリなし)で行い、
**記録に失敗しても投稿処理は止まらない**(ログに残すだけ)。シートIDと鍵はGitHub Secrets
(`SHEET_ID` / `GOOGLE_SERVICE_ACCOUNT_JSON`)で渡し、リポジトリには書かない。

| タブ | 内容 | 記録のタイミング |
|---|---|---|
| 投稿履歴 | 日時・種別(AI/レート)・枠・カテゴリ・切り口・URL有無・tweet_id・本文 | 投稿のたび |
| 投稿成績 | tweet_id・インプレッション・いいね・リポスト・返信・引用・ブックマーク | AI投稿の24時間後 |
| 日次推移 | フォロワー数・フォロー数・総ポスト数・当日の投稿数 | 毎日23:30 JST以降の最初の起動(`daily-snapshot.js`) |
| エラー履歴 | 日時・処理・内容・実行ログのURL | 失敗のたび(同じ内容は60分以内に重複記録しない) |
| フォロバ履歴 | (フォロー機能用。現在は未使用) | — |

- 初期設定(不足タブとヘッダー行の作成。何度実行しても同じ結果): `node setup-sheet.js`
  (アクセス確認だけなら `--check`。環境変数 `SHEET_ID` と `GOOGLE_SERVICE_ACCOUNT_FILE` を設定して実行)
- フォロワー個人の情報(ID・ユーザー名)は、このリポジトリに一切保存しない。

## 自動フォロバ・フォロー解除(`follow.js`)

**既定ではOFF。** 管理シートの「設定」タブで「フォロバ自動化」を `ON` にしたときだけ動く(止めたいときは `OFF` に戻す。コードの変更・pushは不要)。

- 1日1回(10:00 JST以降の最初の起動)。フォロー・解除ともに1日5件まで(設定タブで変更可)
- フォロー対象は先着順。鍵アカウント、アカウント作成から30日以内の相手は除外する
- 解除対象は「Botがフォロバした相手のうち、後でフォロワー一覧から消えた人」だけ。手動でフォローした相手は触らない
- フォロー・解除でエラーが出たら、その日は自動で止める。同じ相手で3回失敗したら対象外にする
- 月予算ガード: フォロー($0.015)・解除($0.010)・一覧読取(設定タブの単価)の概算費用が、Xの請求サイクル(毎月11日開始)で上限($5)に達したら止まる。記録は「API利用」タブ
- フォロワー一覧の全件読み取りは月1回(費用がフォロワー数に比例するため)。候補は「フォロバ候補」タブ、履歴は「フォロバ履歴」タブに残る
- 一覧が欠けている恐れがあるとき(取得人数がプロフィールの人数より大幅に少ない)は、解除候補を作らない
- **ログには、ユーザーID・ユーザー名を一切出さない**(公開リポジトリのActionsログは誰でも見られるため)。個人情報は非公開のシートにだけ置く
- 確認モード: `node follow.js --plan`(ActionsのRun workflowでは `follow_plan` にチェック)。一覧の読み取りと候補の更新だけ行い、フォロー・解除はしない

Xの自動化ルールでは、一括・攻撃的・無差別なフォロー/解除が禁止されており、開発者ガイドラインは「フォローしてきた全員へのフォローバック」を不可の例に挙げている。
上限を小さくしていてもリスクは残るため、フォロー・解除に関するエラーや警告が出たらOFFにして状況を確認すること。

## 年1回のメンテナンスが必要な項目

**`CLAUDE_CODE_OAUTH_TOKEN` は発行から1年で失効します。**
`claude setup-token` はAnthropic側の仕様で有効期限を1年より延長できません
(2026年9月確認済み)。期限が切れると投稿が止まります。

### 更新手順(1年ごと)

1. ターミナルで `claude setup-token` を実行し、ブラウザでログイン・承認
2. 表示された新しいトークン(`sk-ant-oat01-...`)をコピー
3. 以下のコマンドでGitHub Secretsを更新:
   ```
   gh secret set CLAUDE_CODE_OAUTH_TOKEN --repo businessfxtrader-rgb/x-auto-tac-bot --body "<新しいトークン>"
   ```

最終更新: 2026年9月2日発行(次回更新目安: 2027年9月頃)
